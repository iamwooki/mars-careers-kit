# 포트폴리오 PDF

## 문서 구조 (고정)

| 페이지 | 내용 | 원칙 |
|--------|------|------|
| 1p 요약 | 이름·직함·연락처 / 3줄 소개 / 핵심 역량 3개(각 대표성과 1줄) / KPI 하이라이트 4개(숫자 크게) / 경력 타임라인 | **1페이지만 읽어도 채용 판단이 가능해야 한다.** 여기서 못 담으면 뒤도 안 읽힌다 |
| 2p 총괄 | 프로젝트 × 역량 매트릭스 표 (프로젝트명, 기간, 역할, 핵심 성과 1줄) | 상세 페이지의 목차 역할 |
| 3p~ 상세 | 프로젝트 카드당 반 페이지: 문제 → 행동 → 성과(숫자 강조) → 증빙 | 페이지당 2개, 대표 프로젝트는 1페이지 할애 가능 |
| 마지막 | 스킬·도구 / 교육·자격 / (선택) 추천·평가 인용 | 간결하게 |

## 지원처 맞춤화

포트폴리오는 마스터 1개가 아니라 **지원처별 빌드**다:
1. `applications/{지원처}/00_target.md`의 요구 역량 키워드를 읽는다.
2. inventory의 confirmed 카드 중 keywords가 매칭되는 것을 우선 선별·전진 배치한다.
3. 1p 요약의 "핵심 역량 3개"도 지원처 요구 역량 순서로 재정렬한다.
4. 매칭 안 되는 카드는 과감히 제외 — 두꺼운 포트폴리오보다 8~10p의 저격형이 낫다.
5. 지원처가 지정되지 않았으면 전체 카드로 마스터판을 만든다 (`applications/_master/`).

## 생성 절차

1. `assets/portfolio-template.html`을 복사해 `applications/{지원처}/portfolio.html`로 만들고
   플레이스홀더(`{{...}}` 주석 참조)를 실제 내용으로 치환한다.
   구조 변경 없이 내용만 채우는 것이 원칙 — 레이아웃 수정은 템플릿 CSS의 print 규칙을 깨기 쉽다.
2. 렌더링:
   ```powershell
   & "{스킬경로}\scripts\html_to_pdf.ps1" -HtmlPath "...\portfolio.html" -PdfPath "...\portfolio.pdf"
   ```
3. **검수 필수**: 생성된 PDF를 Read 도구로 열어 (a) 페이지 넘김이 어색하게 잘리지 않는지
   (b) 글자 깨짐이 없는지 (c) 1p가 실제로 1페이지에 들어가는지 확인한다.
   내용이 넘치면 내용을 줄인다 — 폰트 크기를 줄여 우겨넣지 않는다 (본문 10pt 미만 금지).

## 디자인 규칙 (템플릿에 이미 반영됨)

- A4 세로, 여백 18mm, 본문 10.5pt, 맑은 고딕 기반
- 색은 포인트 1색(남색 계열)만 — 숫자 성과와 섹션 헤더에만 사용
- KPI 숫자는 크게(24pt+), 단위·설명은 작게
- 표는 가로선만, 장식·아이콘·클립아트 금지
