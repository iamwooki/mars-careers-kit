# 사용 설명서 (self-profile)

## 목적

카드는 프로젝트 단위의 사실이다. 이 문서는 그 사실들을 가로로 읽어 **사람 단위의 그림**을 만든다 — 지원처를 고르고, 자기소개 첫 문장을 정하고,
면접에서 "어떤 사람이냐"는 질문에 근거를 들어 답하기 위한 내부 자료다. 성적·재직 정보·내부 업무가 들어가므로 **비공개**다 (`site/` 반입 금지).

## 원천과 생성물

```
inventory/P*.md (+ profile.md, education.md, applications/, _workspace/의 인터뷰 원자료)
  → self-profile.yaml        ← Claude가 분석해서 쓴다 (양식: assets/self-profile_template.yaml)
  → scripts/build_profile.py
  → self-profile.html        ← 생성물, 직접 수정 금지
```

```
python3 .claude/skills/self-profile/scripts/build_profile.py .
```

프로젝트 표(ID·제목·기간·확정 여부·남은 빈칸 수)는 스크립트가 카드에서 **자동으로** 읽는다. yaml의 `projects`에는 묶음(groups)과,
카드의 한 줄 요약 대신 보여 줄 문구(did/result/title/period)만 적는다.

## 쓰는 원칙

1. **세 가지를 섞지 않는다.** `{사실}`은 카드·증빙으로 확인된 것, `{해석}`은 읽고 내린 판단, `{빈칸}`은 아직 모르는 것. 해석 섹션(패턴·맡을 수 있는 프로젝트·맞는 자리)에는 반드시 근거 카드 `[P07]`를 단다.
2. **근거 없는 역량은 적지 않는다.** 역량 지도의 모든 줄에 카드 번호가 있어야 한다. 점수는 5 = 여러 해 직접 담당·성과 있음, 3 = 담당했지만 짧거나 일부, 2 = 학부·개인 수준, 1 = 접해 본 정도.
3. **숫자의 주인을 가른다.** 이력에 나오는 숫자마다 "무엇의 숫자인가 / 내 몫은 무엇인가"를 적는다. 남이 산출한 값은 산출 주체를, 추정치는 추정이라고 쓴다.
4. **약점을 숨기지 않는다.** "조심할 자리", "경험 자체가 없는 것", 직함과 실제 동사의 간격을 적는다. 이 문서의 독자는 본인뿐이다.
5. **패턴은 3~5개.** 서로 다른 시기의 카드 3장 이상에서 같은 방식이 되풀이될 때만 패턴으로 올린다. 한 번 한 일은 패턴이 아니다.
6. **표현 수위를 남긴다.** 본인이 직접 하지 않은 것(배석, 업체 마무리, AI 도구로 제작 등)은 그 수위 그대로 적는다 — 자소서·면접의 기준이 된다.
7. 문체는 평서문, 짧게. 설명 중간의 대시(—)와 "~를 통해" 반복을 피한다.

## 절차

1. 카드 전부와 profile.md·education.md, 최근 인터뷰 원자료, 지원 현황을 읽는다. 카드 3장 미만이면 중단하고 career-inventory를 권한다.
2. 아래 순서로 yaml을 채운다 (없는 재료의 섹션은 통째로 빼도 된다 — 스크립트가 있는 섹션만 그린다).
   `headline`(두 줄) · `summary`(한 문단) · `tiles` → `timeline`(막대 rows·표시 marks·표 table) → `patterns` → `workmix`(업무 기록을 유형별로 센 자료가 있을 때만)
   → `can_do` → `skills` → `fit` → `projects` → `numbers` → `edu` → `voice`(직접 쓴 글이 `applications/_reference/`에 있을 때) → `gaps` → `todo` → `sources`
3. 빌드하고 headless 브라우저로 렌더를 확인한다(타임라인 막대, 표 넘침).
4. 사용자에게 요약을 말로 전한다: 한 문단 정체성, 패턴 제목들, 가장 큰 빈칸 3개. 해석이 본인 생각과 다른 곳을 묻는다 — 다르면 해석을 고친다(사실은 카드에서 고친다).
5. 갱신: 카드가 확정되거나 인터뷰가 끝날 때마다 yaml의 해당 줄만 고치고 재빌드. `todo`는 상태(`답함`/`절반`/`남음`)를 바꿔 가며 유지한다.

## 글 안의 표기

`[P07]` 카드 칩 · `[P16·P17]` 여러 장 · `{사실}` `{해석}` `{빈칸}` `{내부}` `{주의}` 배지 · `{사실:내 것}`처럼 글자 지정 · `**굵게**`

**yaml 작성 주의**: 문장이 들어가는 값은 큰따옴표로 감싼다. 특히 한 줄짜리 `{key: value}` 안에 배지(`{빈칸}`), 물음표, 쉼표, 콜론이 있으면 파싱 오류가 난다 — 문장형 항목은 여러 줄(block) 형식으로 쓴다. 빌드가 실패하면 오류가 가리키는 줄의 따옴표부터 본다.

## 검증

- 역량 지도·맡을 수 있는 프로젝트의 모든 항목에 카드 번호가 있는가
- "숫자와 그 주인"에 공개 CV·자소서에 쓴 숫자가 빠짐없이 있는가
- 타인 실명, 주민번호·전화번호·비밀번호가 없는가
- self-profile.html이 `site/` 밖에 있는가
